6 · Stack de seguridad — 5 capas en backend
Extensión del archivo Whitelist: .jpg .jpeg .png .webp
Rechaza en el filter de Multer antes de guardar nada en disco. Capa 1 — fácil de falsificar sola
MIME type (Content-Type) Whitelist: image/jpeg, image/png, image/webp
Header enviado por el cliente — tampoco confiable solo. Capa 2 — client-controlled
Magic bytes (file-type lib) Inspecciona la firma binaria real del archivo en backend.
Un .php renombrado a .jpg tiene magic bytes distintos → rechazado. Capa 3 — la más importante ✓
UUID como nombre de archivo El filename original nunca se usa. Se genera un UUID v4.
Path traversal imposible. Sin metadata del cliente en disco. Capa 4 — path traversal ✓
Tamaño máximo 2 MB Límite enforceado por Multer antes de escribir en disco.
Previene ataques de DoS por llenado de volumen. Capa 5 — DoS / disco lleno ✓
JWT obligatorio en endpoint POST /users/me/avatar requiere JwtAuthGuard.
Upload anónimo imposible. Se usa el sub del token para asociar el archivo al usuario correcto. Auth ✓
